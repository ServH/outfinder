## Challenges

1. **Discarded work from Story 3.1** — SharePreview component (13 tests, 1 HIGH fix in code review) was entirely deleted in Story 3.2. Same pattern as Story 2.4 rollback. Root cause: no visual verification of capture output before investing in tests and review
2. **3 HIGHs exceeded ≤1 target** — H1: VoiceOver leak (3.1), H2: inline styles violating className convention (3.2), H3: dead code with orphan tests (3.2). Convention violations should not reach code review
3. **project-context.md still not updated** — second consecutive retro where this was missed. Addressed during this retro as mandatory gate

## Key Insights

1. **Validate visual/capture output on device before writing tests** — two epics now with fully implemented + tested + reviewed work that was discarded (Story 2.4, Story 3.1 SharePreview). Verification before investment prevents waste
2. **On-screen capture > off-screen duplicate** — capturing what the user actually sees (Skia rendering, shadows, aureola) produces superior share images vs. a simplified RN-only recreation
3. **Convention HIGHs are preventable** — the dev agent knows CLAUDE.md rules but still produces inline `style` violations. These should be caught in self-review, not adversarial code review
4. **project-context.md is infrastructure, not a task** — must be treated as a gate, not an optional action item
