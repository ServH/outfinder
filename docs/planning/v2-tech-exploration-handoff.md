## Dilemas-madre sin resolver

El agente debe entender que estos se cruzan con cualquier decisión técnica:

### Dilema 1 — Anti-AI-slop vs LLMs invisibles
ASO actual: "Curated by hand, not generated by AI". Si introduces LLMs (incluso on-device), el positioning se cuestiona. **Posible solución técnica**: Apple Intelligence on-device (iOS 18.1+) puede satisfacer ambos lados — Apple-curated, on-device, free, no slop.

### Dilema 2 — Privacy-first vs Comercial
Brief promete "Zero-Cost privacy-first". Carrusel de compras / afiliados rompe la promesa. **Posible solución**: separar Premium tier (privacy-first puro) de un módulo opcional de shopping (con opt-in explícito y disclaimer).

### Dilema 3 — Pricing strategy
- Segura: mantener €0.99 legacy + lanzar Premium+ €24.99 para nuevos.
- Agresiva: discontinuar €0.99, solo Premium+ €24.99.
- Recurring: introducir tier €2.99/mo además del lifetime.

### Bloque 3 — Pivote a TECH-FIRST (donde se quedó la conversación)
Usuario explicitó: **"no me interesan features, me interesan tecnologías"**. El cuello de botella identificado fue **friction de captura**: 30-60s/prenda × 30 prendas = 22min de trabajo manual = drop-off masivo.

Asistente expuso **7 fuentes de captura** que la app debería aceptar:

| # | Fuente | Tech principal | Esfuerzo |
|---|---|---|---|
| 1 | URL del producto (Zara/Mango/H&M) | Schema.org Product parsing + OG meta + Vision cutout sobre fetched image | 1-2 sem |
| 2 | Screenshot del producto/pedido | VisionKit DataScanner OCR + saliency segmentation + Apple Intelligence multimodal | 2 sem |
| 3 | Bulk shot (toda la ropa, una foto) | Vision rectangle detection / CoreML custom multi-object detector | 3-4 sem |
| 4 | Photos library scan retroactivo | PHAsset enumeration + Vision saliency + classifier "is garment?" | 2-3 sem |
| 5 | Forward email pedido | Mail Extension / App Intent + HTML parsing + Apple Intelligence | 1 sem/retailer |
| 6 | Live capture continuo (auto-snap) | react-native-vision-camera frame processor + stability detection | 2 sem |
| 7 | Wearing-the-garment selfie | VNGeneratePersonSegmentationRequest + Subject Lift + WB pipeline | 3-4 sem |

### Bloque 4 — Tecnologías propias para construir (moat)

| Concepto | Qué es | Por qué moat |
|---|---|---|
| **WadaCoreML** | Custom CoreML classifier entrenado con dataset propio (fashion items + Wada tone labels) | Outperformá MobileNetV2 generic 10x. Imposible de copiar sin dataset propio. |
| **WadaKit** | Swift Package distribuible (WB + cutout + Wada matching + categorización) | Open-core: free para no-comercial, license B2B. Revenue colateral. |
| **WadaSense color constancy** | Productización del WB module v1.3 — lighting-aware color extraction | Competidores extraen pixel naïve, fallan con luz cálida. Tu pipeline no. |
| **Wadapedia content engine** | Datos curados (historia/pintor/mood) por combo + Apple Intelligence runtime | Datos > código. La competencia no puede generar este contenido. |
| **Outfinder URL Resolver** | Parser de fashion retailers → `{image, name, color, brand}` | B2B sellable a aggregators. Maintenance ongoing. |
| **Wada AR Material Library** | Cada combo como RealityKit Material para AR/Vision Pro | Cuando VP v2 explote (rumor finales 2026), llegas con catálogo materials propietario. |

### Bloque 6 — Top 3 apuestas tech del asistente

Si el usuario invierte capital técnico en 3 cosas:

1. **App Intents + URL Resolver + Schema.org parser** (4-6 sem) — friction 45s→5s por prenda. Multiplica valor de todas las demás features.
2. **WadaCoreML classifier** (4-6 sem incl. dataset) — single biggest quality leap. Moat permanente.
3. **Apple Intelligence integration** (2-3 sem) — Resuelve dilema 1 + queries naturales gratis + Image Playground gap-filler.

Las tres juntas justifican subida honesta a €25-30 lifetime.

### Bloque 7 — Wild card: proprietary haptic language
Usar CHHapticEngine para diseñar patrones háptcos custom (tap-success-Wada-match, tap-warning-partial, tap-save-successful con resonancia tipo cierre de broche). Brand sensorial inimitable.
